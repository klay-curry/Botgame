## 1. 模块总览：干什么、能带来什么、值不值得

预算约束决定了排序逻辑：**GPU 时间是稀缺资源**（4 周里大约只够 8–12 次全量训练），所以"不占 GPU 就能有收益"的事优先级最高；**评测分数一半来自 randomized**，所以一切能改善 unseen 泛化的改动权重更大；**改形级改动（动参数形状）全部判死**——那会让预训练权重失效，等于从零训练。

**读表方法**：P0 三项（评测基建、训练配方、数据增强）合计预期贡献 >80% 的收益，且互相不阻塞，是两周内的全部主战场；P1 在 P0 出结果后插入；P2 只在前两层完成后还有 GPU 富余时才启动。**上届挑战赛报告是所有预期数字的锚**（`G:\document\papers\Embodied AI\RoboTwin Dual-Arm Collaboration Challenge at CVPR 2025.pdf`），动手前先读方案总结部分校准预期。

## 2. 分工：两条线

**梁家诚 — "训练与模型"线**（模块 1 执行 + 2 + 5）
- 主线是训练配方：从 checkpoint 扫描开始，这是性价比之王；
- action-head 是模型核心的学习入口，配置级实验顺手做；
- 云机申请/管理本就由你负责（沿用团队既定安排），训练实验与 GPU 排期天然同轨。

**刘勇泽 — "数据与基建"线**（模块 1 协议设计 + 3 + 4 + 7 调研）
- 主线是数据增强：三条 P0 里唯一的代码开发项，且独占"randomized 泛化"这个得分半壁；
- 数据审计是增强的前置（知道数据长什么样才知道怎么增强）；
- vision-encoder 以调研和方案为主（P2，不急于写代码）。

**模块 1（评测基建）两人共建**：快筛协议设计、结果格式由刘勇泽定稿（他要靠它做数据/格式核对），调度脚本与云端执行由梁家诚落——评测是两条线的共享货币，谁也离不开谁。

## 3. 每个负责人的第一份产出（本周，不需要 GPU）

把自己名下模块的 `README.md` 写出来，四个必含小节：

1. **涉及文件**：模块覆盖的代码文件逐个一句话职责说明；
2. **数据流**：张量/数据从进到出，标关键 shape；
3. **可改点清单**：按 A 配置级 / B 加法级 / C 死路 三级标注；
4. **当前默认值**：对应 yaml 现值（后续所有实验的基线）。

第二份产出：`refs/` 放 2–3 篇入门笔记。推荐起点——训练配方/动作头 → π0 论文 + 上届挑战赛报告；数据增强 → RoboTwin 2.0 论文（randomized 到底随机了什么）+ ACT（小数据 BC 的增强与早停经验）；视觉外挂 → LingBot-VLA 2.0 论文（蒸馏旁路设计动机）。

## 4. 改代码的位置：副本制度

- `ours/`（仓库根目录）是官方代码**可修改副本**（入库），一切训练/评测/修改在它上面进行；我们的原创脚本（审计、快筛调度、分析工具）放根目录 `scripts/`；
- `lingbot-vla-v2/` 是**原始参照**（不入库，保持 clone 原状），改坏了用来对照：

  ```bash
  # 对比单个文件
  git diff --no-index lingbot-vla-v2/lingbotvla/schedulers/flow_match.py ours/lingbotvla/schedulers/flow_match.py
  # 一键列出我们改过的所有官方文件
  git diff --no-index --stat lingbot-vla-v2/ ours/
  ```

- 复现报告写法：`官方代码 v<commit> + 本仓库 git 历史全部 diff`；
- 本文档与各模块 README 中列出的官方文件路径，均相对 `ours/`。

## 5. 目录规则

```
docs/modules/<模块名>/
├── README.md      # 模块地图（§3 四节）+ 状态表
├── refs/          # 参考论文笔记、文档链接（PDF 放个人论文库，这里放笔记）
└── proposals/     # 一个方案一个文件：P<n>-<主题>.md，头部标"状态: 草案|评审中|已排期|已验证|已推翻"
```

- **推翻规则**：不删不改旧 proposal；新建文件头标 `supersedes: P<n>-<旧主题>`，同步更新模块状态表；
- **与实验衔接**：proposal"已排期" → 开实验分支 → 按 [TEMPLATE](../experiments/TEMPLATE.md) 记录 → 回填 proposal 状态与结论；
- 分工想调整：改本文件表格并走 PR，说明理由。
