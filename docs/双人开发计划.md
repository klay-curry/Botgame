# 双人开发计划（2026-09-28 至 2026-10-26）

## 目标与角色

比赛要求以指定 LingBot-VLA 2.0 预训练权重为起点，只用 RoboTwin 2.0 Aloha-AgileX 的 50 个任务、每任务 50 条 clean 数据训练；最终提交同一 checkpoint 在 clean/randomized 两个 setting 各 50×100 次的评测结果及复现材料。具体规则以[天池赛题](https://tianchi.aliyun.com/competition/entrance/532514/information)和 `docs/灵波2026/` 模板为准。

刘勇泽和梁家诚技术背景接近、都能投入较多时间。分工按**主要交付物和设备职责**划分，不按 Mac/Windows 限制谁能写模型代码。梁家诚负责统筹 AMD 算力申请与管理；两人均需按 [AMD 官方申请指南](https://github.com/AMD-DEV-CONTEST/Embodied-AI-Challenge-AMD-Platform-2026-09)填写申请表，队长和资源接收人以实际登记为准。训练、评测都在 Linux 云端运行，双方都应有只读查看日志和必要的远程操作能力。

| 工作流 | 刘勇泽（主责） | 梁家诚（主责） | 交叉验收 |
| --- | --- | --- | --- |
| 规则与数据 | 核对赛题/模板；实现 50×50 clean 数据审计、训练清单和 clean-only 统计；维护 `src/data/` | 提供云端实际数据路径、下载记录和文件清单 | 梁家诚复核 50 个任务、每任务 50 条，训练路径无 randomized |
| 模型训练 | 设计基线与单变量实验；维护 `configs/train/`、`train.sh`；记录 loss、耗时和 checkpoint；提出最终候选 | 提供/维护 GPU 环境，执行或协助执行长训练、断点恢复、持久化和备份 | 梁家诚复核训练命令、资源消耗、模型来源及 checkpoint 可加载性 |
| 云端环境 | 完成个人 AMD 申请表；提供需要固定的模型/数据/代码 revision，审查下载与环境脚本 | 协调两人填报、申请/管理 AMD 算力；维护 `scripts/setup_repos.sh`、`scripts/download_*.sh` 及云端环境；记录 GPU、存储和额度 | 刘勇泽在云端独立复跑环境检查与一次模型推理 |
| 闭环评测 | 定义结果格式、核对 100 个 setting-task 的日志与 JSON；维护最终复现报告 | 维护 `eval.sh`、`src/eval/`；跑单任务 smoke、方向性评测和正式评测；保留失败日志和续跑状态 | 刘勇泽复核 checkpoint 哈希、评测配置及逐任务 attempts/successes |
| 提交 | 整理 `README`、复现报告和 ZIP，负责平台提交及回执保存 | 在另一台机器解包、加载权重、检查目录和 JSON，并留备份 | 两人共同签字确认最终 checkpoint 与 results.json 对应 |

如赛事账号由梁家诚实际管理，最后一行的平台提交执行人交换，复核责任不变。任何人都能提出实验，但长训练、换 checkpoint 或开始正式评测前，两人先确认预计 GPU-hours 与截止时间。

## 工作接口：交给对方时必须带什么

- **数据交给训练：**50 个任务名单、各任务 50 条的计数、数据 revision/哈希、clean-only LeRobot 路径、归一化统计路径和生成命令。
- **训练交给评测：**唯一 checkpoint 路径和 SHA-256、预训练权重来源、代码 commit、训练配置快照、robot config、精度和加载 smoke 结果。
- **评测交给提交：**每个 setting/任务的原始日志、实际 attempts/successes、评测 commit/seed/精度/环境、失败清单、按官方模板生成的 `results.json`。
- **交接方式：**在对应 PR 或 `docs/experiments/` 记录链接和文件哈希；大文件用云端持久目录共享，Git 只存可复现说明。路径用环境变量或配置传递，避免把 `C:\...`、`/Users/...` 写进共享脚本。

## 两人每天的最小协作节奏

1. 开工前各自说清今天要改的文件和预计占用的 GPU 时间；同一文件由一人先改。
2. 当天结束前提交小 PR、实验记录和真实验证结果，另一人在当天或次日开工前复核。
3. 每晚更新“已完成、阻塞、下一步”；每两三天对照上表判断是否需要削减实验范围。
4. 资源不足时先保**可复现基线、完整评测和有效提交**，真机 Demo、复杂结构改造和额外宣传内容排在后面。

Git 的具体操作、提交格式、PR 验收和文件安全边界见仓库根目录 [CONTRIBUTING.md](../CONTRIBUTING.md)。
